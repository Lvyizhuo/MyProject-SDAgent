# 日志规范

> 适用范围：后端（Spring Boot）、重排服务（Python/FastAPI）、前端（Nginx）。
> 第三方中间件（PostgreSQL / Redis / MinIO / Ollama）见文末「例外说明」。

## 一、统一目标

| 维度 | 规则 |
| :--- | :--- |
| 格式 | ISO-8601 带时区时间戳开头 + 级别 + PID + 组件名 + 线程/来源 + logger + 消息 |
| 命名 | **`<组件名>-<YYYY-MM-DD>.log`**，例：`backend-2026-11-10.log` |
| 切分 | 纯按容量（单文件 100MB），**不压缩**，便于直接查看 / grep / tail |
| 保留 | 30 天（启动时按 mtime 清理） |
| 目录 | 本地 `<repo>/logs/`；容器内统一 `/app/logs/` |
| 读取 | `./scripts/deploy.sh logs <svc>`（容器 stdout）<br>`./scripts/deploy.sh logfiles`（容器内文件位置） |

## 二、格式规范

### 后端（Logback）

`backend/src/main/resources/logback-spring.xml` 直接复用 Spring Boot 3.4.1 内置的
`CONSOLE_LOG_PATTERN` / `FILE_LOG_PATTERN`，**不自定义格式**。
控制台带 ANSI 颜色、文件不带，除颜色外两者逐行同构：

```
2026-11-10T13:19:50.541+08:00  INFO 1 --- [policy-agent] [http-nio-0.0.0.0-8080-exec-1] o.a.c.c.C.[Tomcat].[localhost].[/]  : Initializing Spring DispatcherServlet 'dispatcherServlet'
```

### 重排服务（Python 标准库 logging）

`rerank-service/server.py` 的 `Iso8601Formatter` + `_build_logging()`，
时间戳用 `datetime.fromtimestamp(...).astimezone().isoformat(timespec="milliseconds")`，
与 Java 的 `%d{yyyy-MM-dd'T'HH:mm:ss.SSSXXX}` 完全一致：

```
2026-11-10T13:21:47.123+08:00  INFO 1 --- [reranker][MainThread] rerank-service : 模型加载完成: BAAI/bge-reranker-v2-m3 (耗时 0.3s)
```

uvicorn 通过 `log_config=None` 启动，其 `uvicorn.error` / `uvicorn.access` 也走同一 formatter。

### 前端（Nginx）

`frontend/nginx.conf` 定义 `log_format unified`，采用「时间戳 + key=value」结构：

```
2026-11-10T13:24:12+08:00 component=frontend type=access status=200 method=GET uri=/index.html bytes=1568 rt=0.000 client=172.19.0.1 ua="curl/8.7.1"
```

`/health` 探针路径 `access_log off`，不产生噪声。

## 三、存储规范

### 目录布局

```
本地 <repo>/logs/                    容器 /app/logs/
├── backend-2026-11-10.log           ├── backend-2026-11-10.log
├── backend-2026-11-10.1.log         ├── backend-2026-11-10.1.log
├── backend-2026-11-10.2.log         ├── reranker-2026-11-10.log
├── frontend.log                      ├── frontend-2026-11-10.log
└── frontend-2026-11-10.log          └── frontend-error.log
```

- `<组件名>-<日期>.log` —— 活动文件（当天）
- `<组件名>-<日期>.<序号>.log` —— 超过 100MB 后的容量切分片（最多 30 个）
- `frontend-error.log` —— nginx 错误日志（nginx 的 `error_log` 路径不支持变量，只能用固定名）

### 按天切换如何实现

三个组件的机制不同，但结果一致：

| 组件 | 机制 |
| :--- | :--- |
| 后端 | 启动时注入 `LOG_DATE`（当天日期）→ 活动文件名 `backend-<日期>.log`；**进程重启即切换到新日期文件** |
| 重排服务 | 同上，`LOG_DATE` 未注入时自行取当天日期 |
| 前端 | nginx `map $time_iso8601 $log_date` 提取日期，`access_log /app/logs/frontend-$log_date.log`；每天 00:05 由 busybox crond 发 `USR1` 触发 reopen，nginx 用新日期另开文件 |

> **已知取舍**：进程连续运行跨越零点时（后端 / 重排服务），日志会继续写入启动日那个文件，
> 直到下次重启才切换。这是"文件名 = 内容日期"与"进程不重启"之间的固有取舍。
> 前端通过每日 reopen 不受影响。

### 切分策略（为什么不用 logback 内置的按天归档）

Spring Boot 内置的 `SizeAndTimeBasedRollingPolicy` 强制要求 `fileNamePattern` 含 `%d`，
而 `%d` 取的是**滚动触发那一刻**的日期 —— 11-11 00:00 触发滚动时，归档文件名会是
`2026-11-11`，装进去的却是 11-10 的内容，**文件名与内容错位一天**。

因此改用：

```xml
<rollingPolicy class="ch.qos.logback.core.rolling.FixedWindowRollingPolicy">
    <fileNamePattern>${LOG_DIR}/${APP_NAME}-${LOG_DATE}.%i.log</fileNamePattern>
    <minIndex>1</minIndex>
    <maxIndex>30</maxIndex>
</rollingPolicy>
<triggeringPolicy class="com.shandong.policyagent.support.logging.SizeOnlyTriggeringPolicy">
    <maxFileSize>100MB</maxFileSize>
</triggeringPolicy>
```

`FixedWindowRollingPolicy` 不要求日期占位符；`SizeOnlyTriggeringPolicy`
（项目自定义，见 `backend/.../support/logging/SizeOnlyTriggeringPolicy.java`）
只按文件大小触发，**不做按天判定**，从而彻底消除日期错位。

### 保留期

30 天，由**启动时按 mtime 清理**：

| 位置 | 实现 |
| :--- | :--- |
| 本地 | `scripts/dev.sh` → `purge_expired_logs()`（`scripts/lib/common.sh`） |
| 后端容器 | `backend/entrypoint.sh` 启动时 `find ... -mtime +30 -delete` |
| 重排容器 | `server.py` 的 `_purge_expired_logs()` |
| 前端容器 | `frontend/docker/log-rotate.sh` 每日 00:05 清理 |

### 路径如何确定

| 场景 | 活动文件 | 归档 |
| :--- | :--- | :--- |
| 本地开发 | `<repo>/logs/backend-<日期>.log` | `<repo>/logs/backend-<日期>.<序号>.log` |
| 一键部署 | `/app/logs/backend-<日期>.log` | `/app/logs/backend-<日期>.<序号>.log` |

- `LOG_DATE`：由 `scripts/dev.sh`（`export LOG_DATE="$(date +%Y-%m-%d)"`）或
  `backend/entrypoint.sh`（`export LOG_DATE=$(date +%Y-%m-%d)`）注入
- `LOGGING_FILE_PATH`：`scripts/dev.sh` 导出 `<repo>/logs`；compose 注入 `/app/logs`

## 四、读取方式

```bash
# 容器 stdout（所有组件统一入口）
./scripts/deploy.sh logs backend
./scripts/deploy.sh logs frontend
./scripts/deploy.sh logs reranker
./scripts/deploy.sh logs all          # 全部容器

# 容器内按天的日志文件
./scripts/deploy.sh logfiles           # 打印各容器的文件位置

# 直接进容器看
docker exec policy-agent-backend-1 tail -f /app/logs/backend-$(date +%F).log
docker exec policy-agent-frontend-1 ls -la /app/logs/
```

本地开发：

```bash
tail -f logs/backend-$(date +%F).log
```

## 五、例外说明

1. **第三方中间件**（PostgreSQL / Redis / MinIO / Ollama）
   应用层无法改写其日志格式，保留上游原生格式（如 PostgreSQL 的
   `2026-11-09 15:21:48.177 UTC [27] LOG:`）。
   存储上统一由 Docker `json-file` 驱动承接（`max-size: 10m` / `max-file: 3`，
   见两份 compose 的 `logging` 段），读取方式与其他组件一致
   （`./scripts/deploy.sh logs postgres`）。
   如需长期留存或统一格式，需要引入日志采集层（fluent-bit / promtail → Loki），超出本次范围。

2. **前端 error.log**
   nginx 的 `error_log` 路径不支持变量，只能用固定名 `frontend-error.log`。
   nginx 的 access_log 支持变量，因此可以是 `frontend-<日期>.log`。

3. **容器重建即丢日志**
   日志写在容器可写层（未挂卷），`docker compose up --build` 重建容器后 `/app/logs` 会清空。
   这是"日志保存在容器内部"的既定取舍。若需跨重建保留，把 `/app/logs` 挂成数据卷即可。

4. **磁盘占用**
   不压缩 + 30 天保留，单个组件最坏情况约 100MB × 30 = 3GB。
   磁盘紧张的机器可调小 `logback-spring.xml` 的 `maxFileSize` 或缩短保留天数。

## 六、相关文件

| 文件 | 作用 |
| :--- | :--- |
| `backend/src/main/resources/logback-spring.xml` | 后端日志格式 / 命名 / 切分策略 |

| `backend/src/main/resources/application.yml` | `logging.file.path` / `app.log.date` / `app.log.name` |
| `backend/entrypoint.sh` | 注入 `LOG_DATE`、清理过期日志、启动 JVM |
| `backend/Dockerfile` | 创建 `/app/logs` 并授权给非 root 用户 |
| `rerank-service/server.py` | 统一 formatter + `RotatingFileHandler` + 过期清理 |
| `rerank-service/Dockerfile` | 创建 `/app/logs` |
| `frontend/nginx.conf` | `log_format unified` + `map` 提取日期 + 双写 stdout |
| `frontend/docker/log-rotate.sh` | 每日 reopen（USR1）+ 清理过期文件 |
| `frontend/docker/crontab` | busybox crond 任务表（每日 00:05） |
| `frontend/Dockerfile` | 创建 `/app/logs` 并 chown 给 nginx 用户 |
| `deploy/docker-compose.yml` | 注入 `LOGGING_FILE_PATH` / `LOG_RETENTION_DAYS` |
| `scripts/dev.sh` | 导出 `LOG_DATE` / `LOGGING_FILE_PATH`，启动时清理过期日志 |
| `scripts/lib/common.sh` | `purge_expired_logs()` |
| `scripts/deploy.sh` | `logs all` / `logfiles` 子命令 |
